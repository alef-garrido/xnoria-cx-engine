# CX Intelligence Engine (XNORIA): The Orchestration Layer

**XNORIA - CX Intelligence Engine** is an intelligence engine layering that sits on top of business operating systems (automation, CRM, support). It interprets customer signals, diagnoses experience issues, and generates prioritized action plans.

The engine transforms dispersed data into actionable insights, moving from simple automation to **operational intelligence**.

## Architecture

The system follows a strict 4-layer architecture to ensure security, modularity, and auditability:

1.  **Signal Layer (Radar)**: Captures events and operational data (CRM, Support, Marketing) and transforms them into structured CX signals.
2.  **Orchestration Layer (n8n)**: Coordinates flows, normalizes signals, and manages triggers. It handles execution but does not make decisions.
3.  **Cognitive Layer (OpenClaw)**: The core engine. It interprets signals, detects problems, prioritizes interventions, and generates action plans (Compass + Atlas).
4.  **Execution Layer**: External systems (APIs, CRMs, Human intervention) that execute the plans generated by the cognitive layer.

## Core Principles

-   **Strict Separation**: The cognitive layer **decides**; the orchestration layer **executes**. The engine never executes actions directly.
-   **Security by Architecture**: No direct trust in AI agents. All actions are validated by the orchestration layer.
-   **Observability**: Every signal, diagnosis, and decision is traceable and auditable.
-   **Modularity**: The cognitive engine is interchangeable and modular.
-   **Explainability**: Every output is justified based on input signals, avoiding "black box" operations.

## Key Components

### OpenClaw/Agentic Core (Cognitive Layer) Separate Repo
The engine responsible for interpreting customer signals and generating structured action plans. It leverages dual-context grounding (Base + Domain) to ensure accuracy.

### CX Tool Dock (UI / Visual Layer) Separate Repo
The intake system that monitors business events and translates them into a standardized format for the engine.

### n8n Workflows Engine (Orchestration Layer) This Repo
The "nervous system" of the engine, routing data between layers and ensuring guardrails are met before execution.

## System Dependencies

This project relies on external systems for grounding and execution:

### 1. notebooklm-mcp-server (REQUIRED)
Exposes NotebookLM contexts to the cognitive skills.
- **Base Context**: `Context_Agnostic_Base_v1.0`
- **Domain Context**: `Context_Clinic_Instance_v1.0` (example)

### 2. Gemini Workspace Configuration
Requires a local `/.agent/notebooks.json` (not committed) mapping context IDs to NotebookLM IDs.

## Getting Started

1.  **Clone the repository**:
    ```bash
    git clone git@github:alef-garrido/xnoria-cx-engine.git
    ```
2.  **Configure MCP**: Ensure your AI agent (e.g., Antigravity) has access to the skills in `.agent/skills/`.
3.  **Import Workflows**: Load the JSON definitions from `workflows/` into your n8n instance.
4.  **Setup Grounding**: Configure `notebooks.json` with your NotebookLM IDs.
